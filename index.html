การประยุกต์ใช้ Object-Oriented Design Patterns & หลักการ SOLID Principles

สถาปัตยกรรมเชิงวัตถุระดับสูง (High-Level OOP Architecture)

โครงสร้างระบบถูกออกแบบให้แยกหน้าที่กันอย่างชัดเจน (Decoupled) ระหว่าง Domain Models, Abstract Scraper Interfaces, Platform Subclasses, Currency Services และศูนย์กลาง Price Comparison Engine

- _converter: ICurrencyConverter
- _targetCurrency: string

+ unregisterScraper(name: string)

«abstract» BaseScraper Template Pattern
+ platformName: string (abstract)
+ baseUrl: string (abstract)
+ scrape(keyword): Product[] (Template Method)
# fetch(keyword)*: rawData[]
# parse(rawData)*: Product[]
+ validate(products): Product[]

ลำดับวงจรชีวิตของ Template Method (Lifecycle Sequence)

เมธอด BaseScraper.scrape(keyword) กำหนดโครงสร้างการทำงานตายตัวที่แน่นอน โดยคลาสลูกจะเขียนโค้ดเฉพาะส่วนดึงและแปลงข้อมูลของแพลตฟอร์มตนเอง โดยไม่สามารถข้ามหรือเปลี่ยนลำดับขั้นตอนได้

S • Single Responsibility Principle

Product รับผิดชอบเฉพาะข้อมูลสินค้า, Scraper รับผิดชอบเฉพาะการดึงข้อมูล และ Engine รับผิดชอบประสานงาน

O • Open / Closed Principle

สามารถเพิ่มสแครปเปอร์ใหม่ เช่น Amazon ในขณะทำงานผ่าน registerScraper() ได้โดยไม่ต้องแก้โค้ดเดิม
