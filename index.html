High-Level Object-Oriented Architecture

The project is cleanly decoupled into Domain Models, Abstract Scraper Interfaces, Platform Subclasses, Currency Services, and a central Price Comparison Engine.

Template Method Lifecycle Sequence

The BaseScraper.scrape(keyword) method defines the invariant execution skeleton. Subclasses implement platform data retrieval without modifying the overall lifecycle:

1
fetch(keyword)

Abstract step. Subclass contacts marketplace API and returns raw payload.

→
2
parse(rawData)

Abstract step. Converts platform-specific JSON/satang into domain Product objects.

→
3
validate(products)

Concrete step in base class. Filters out corrupted data, negative prices, or empty names.

S • Single Responsibility

Product holds domain state. Scrapers only handle extraction. PriceComparisonEngine only coordinates aggregation & sorting.

O • Open / Closed Principle

New scrapers (e.g. Amazon, TikTok Shop) can be registered at runtime via registerScraper() with zero modifications to existing classes.

L • Liskov Substitution

All scraper subclasses seamlessly replace BaseScraper without altering the correctness or contract expected by the engine.

I • Interface Segregation

Scrapers only implement the methods they need (fetch & parse), keeping interfaces minimal and uncluttered.

D • Dependency Inversion

The high-level engine depends upon abstractions (BaseScraper and ICurrencyConverter) rather than concrete platforms or hardcoded exchange rates.
